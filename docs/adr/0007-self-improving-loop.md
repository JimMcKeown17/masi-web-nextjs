# The self-improving loop: capture draft-vs-final diffs, promote autonomy on evidence

Every drafting agent stores its `draft_body`. When Jim sends, the rail syncs back the `final_body` (Gmail sent-mail for Personal Sends; the Mailchimp API for broadcasts). The diff between the two is captured and classified (`edit_capture.classify` -> magnitude + categories: voice / facts / structure / killed). Those classified edits feed three things: the Voice Guide (quarterly recalibration), the Answer Library (accepted grant answers become blocks/variants), and the autonomy dial (per-agent, per-audience promotion criteria stated in numbers). This is a foundation, built into the spine schema in Layer 1, not a later phase.

Why: Jim named the self-improving loop his top priority, and it is the only mechanism that turns "Jim's curation time" — the system's documented bottleneck — from a constant into a declining curve. The autonomy dial (ADR 0003) is otherwise a metaphor: without the diff, the decision to raise it ("Tier 3 newsletter auto-send becomes eligible at >=95% approve-without-edit over trailing 20 issues") gets made on vibes. The data is nearly free to collect because the rails already read sent mail and the final campaign body — but only if `draft_body` is stored with a stable id from day one. The early signal is unrecoverable later, which is why this cannot wait for a "metrics phase."

Consequences: two text columns and a classification step per draft, from the first send. The loop is an apprentice studying the editor's red pen — it updates curated artifacts (Voice Guide, Answer Library) and surfaces dial-promotion evidence; it does not fine-tune a model or modify its own behavior autonomously. Raising any dial remains an explicit human decision, now backed by a number.

Considered: capturing only the binary approve/reject (cheaper, but throws away the gradient that makes voice learnable); a separate analytics phase later (rejected — the signal from the first months is the most valuable and is gone if not captured at the source).

Informed by the Hermes agent (nousresearch/hermes-agent, reviewed 2026-06-13): Hermes runs the same shape — agent-curated memory, "skills self-improve during use," autonomy levels gated by command approval. Two ideas borrowed while keeping our narrower boundary: (1) the loop runs in *two directions* — corrective (capture the editor's red pen, which this ADR already does) AND generative (after a successful novel task, crystallize the pattern into a reusable unit — for us, a won application or a well-received issue proposes a new Answer Block or Voice Guide rule, Hermes' "autonomous skill creation after complex tasks"); (2) cross-session recall via summarization is a good implementation note for `contact.history` once timelines grow long. Deliberately NOT adopted: Hermes' autonomous execution (terminal backends, container isolation, acting across Telegram/Discord). Our safety model is the opposite bet — the narrow draft-only write surface (ADR 0003); the loop updates curated artifacts and surfaces dial-promotion evidence, but humans still send.
